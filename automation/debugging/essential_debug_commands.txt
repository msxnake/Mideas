## QUICK START DEBUG SESSION

1. Launch debugging:
   start_debug_session

2. Run automated tests:
   run_debug_tests

3. If no graphics appear, try manual setup:
   manual_vdp_setup


## MANUAL DEBUGGING COMMANDS

### VDP Investigation
check_vdp_status                    # Check VDP registers and mode
check_vram_contents                 # Examine all VRAM areas
vdp info reg 0                      # Check specific VDP register
vdp info vram 0x1800                # Check specific VRAM address

### CPU State
check_cpu_state                     # CPU registers and memory context
reg PC                              # Current program counter
reg SP                              # Stack pointer
peek 0x4000                         # Read memory byte

### ROM Analysis
analyze_rom_structure               # Check ROM header and code
hex_dump 0x4000 64                  # Hex dump of ROM start

### Breakpoints and Execution
debug set_breakpoint 0x4000         # Set breakpoint at address
step 1000                           # Execute 1000 instructions
run                                 # Continue execution

### Screenshots and Logging
take_screenshot "test"               # Take screenshot with name
show_debug_help                     # Show all available commands


## COMMON DEBUGGING SCENARIOS

### Scenario 1: ROM loads but no graphics
1. check_vdp_status                 # Verify Screen 2 mode
2. check_vram_contents              # Check if data is in VRAM
3. manual_vdp_setup                 # Force proper VDP setup

### Scenario 2: ROM doesn't execute properly
1. analyze_rom_structure            # Check ROM header
2. debug set_breakpoint 0x4000      # Break at ROM start
3. step 10                          # Step through initialization
4. check_cpu_state                  # Check registers

### Scenario 3: Sprites not visible
1. Check sprite attribute table:
   vdp info vram 0x1B00             # First sprite Y position
   vdp info vram 0x1B01             # First sprite X position
   vdp info vram 0x1B02             # First sprite pattern
   vdp info vram 0x1B03             # First sprite color

2. Check sprite patterns:
   hex_dump 0x3800 64               # First sprite patterns

### Scenario 4: Background tiles not showing
1. Check name table:
   hex_dump 0x1800 256              # Pattern name table

2. Check pattern generator:
   hex_dump 0x0000 256              # Pattern definitions

3. Check color table:
   hex_dump 0x2000 256              # Color definitions


## VDP REGISTER MEANINGS (Screen 2)

R0 (Mode Register 0):
  - Bit 1: M3 (Graphics mode bit)
  - Should be 0x02 for Screen 2

R1 (Mode Register 1):
  - Bit 7: Screen enable (1=on)
  - Bit 6: M1 (Graphics mode bit)
  - Bit 5: M2 (Graphics mode bit)
  - Bit 4: Size (0=8x8, 1=16x16 sprites)
  - Should be 0xE2 for Screen 2 with 16x16 sprites

R2 (Name Table Base):
  - Value * 0x400 = Name table address
  - Should be 0x06 for address 0x1800

R3 (Color Table Base):
  - For Screen 2: should be 0xFF (address 0x2000)

R4 (Pattern Generator Base):
  - Value * 0x800 = Pattern table address
  - Should be 0x03 for address 0x0000

R5 (Sprite Attribute Base):
  - Value * 0x80 = Sprite attribute address
  - Should be 0x36 for address 0x1B00

R6 (Sprite Pattern Base):
  - Value * 0x800 = Sprite pattern address
  - Should be 0x07 for address 0x3800

R7 (Colors):
  - Upper 4 bits: Text color
  - Lower 4 bits: Background color
  - 0xF1 = White text on black background


## VRAM MEMORY MAP (Screen 2)

0x0000-0x17FF: Pattern Generator Table (6KB)
0x1800-0x1AFF: Pattern Name Table (768 bytes)
0x1B00-0x1B7F: Sprite Attribute Table (128 bytes)
0x2000-0x37FF: Color Table (6KB)
0x3800-0x3FFF: Sprite Pattern Table (2KB)


## COMMON ISSUES AND SOLUTIONS

Issue: "ROM too small (38 bytes)"
Solution: Compilation failed. Check ASM code for syntax errors.

Issue: "Screen stays black"
Solution:
1. Check if Screen 2 mode is set correctly
2. Verify VDP registers with check_vdp_status
3. Try manual_vdp_setup

Issue: "No sprites visible"
Solution:
1. Check sprite data is loaded in VRAM (0x1B00+)
2. Check sprite patterns exist (0x3800+)
3. Verify sprite coordinates are on screen

Issue: "ROM starts but freezes"
Solution:
1. Set breakpoint and step through code
2. Check for infinite loops
3. Verify stack pointer is valid

Issue: "Graphics corrupted"
Solution:
1. Check VRAM contents for correct data
2. Verify color table is properly set
3. Check for memory overwrites
